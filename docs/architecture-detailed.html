SDK Internal Architecture (@shalwin04/x404r-sdk)

Core x404r Client

Main entry point. Initializes backend, AI provider, manages workflows.

INPUT: Config
{ mode: 'embedded' | 'cloud', connectionString: 'postgresql://...', ai: { provider: 'gemini' | 'openai' | 'anthropic', apiKey: '...' }, tenantId?: 'uuid', debug?: boolean }
OUTPUT: Runtime Instance
runtime.workflow() // Define workflows runtime.worker() // Create workers runtime.submit() // Submit jobs (cloud) runtime.status() // Check job status

Builder WorkflowBuilder

Defines workflow structure with steps, dependencies, handlers.

INPUT: Workflow Definition
{ name: 'process-documents', version: '1.0.0', steps: [ { name: 'extract', handler: async (ctx) => {...}, dependsOn: [] }, { name: 'summarize', dependsOn: ['extract'], handler: async (ctx) => {...} } ] }
OUTPUT: Executable Workflow
workflow.run(input, { wait: true }) → Promise<{ workflowId, status, output }>

Execution Worker

Claims and executes tasks. Manages heartbeats and checkpoints.

INPUT: Worker Config
{ concurrency: 5, // Max parallel tasks pollInterval: 1000, // Poll every 1s heartbeatInterval: 10000, // Heartbeat 10s taskTypes: ['extract'] // Optional filter }
OUTPUT: Worker Actions
worker.register(workflow) // Add workflow worker.start() // Begin processing worker.stop() // Graceful shutdown worker.activeTaskCount // Current tasks

Context StepContext

Passed to handlers. Provides state, checkpointing, AI access.

INPUT: Available Properties
ctx.input // Step input data ctx.state // Last checkpoint state ctx.workflow // { id, name, version } ctx.task // { id, name, attempt } ctx.ai // AI provider instance
OUTPUT: Available Methods
await ctx.checkpoint({ progress: 5 }) await ctx.ai.generate('prompt') await ctx.ai.generateJSON('prompt') ctx.log('message', { data }) await ctx.sleep(1000)

AWS Lambda Functions — Detailed I/O

Lambda Worker Function

Triggered by EventBridge every 1 minute. Claims and executes tasks.

INPUT: EventBridge Event
{ "action": "process" | "reclaim", "taskId"?: "uuid" // For specific task }
1
Claim Task (CockroachDB)
SELECT * FROM task_nodes WHERE status = 'pending' AND dependencies_met = true ORDER BY priority DESC FOR UPDATE SKIP LOCKED LIMIT 1;
2
Load Checkpoint
SELECT state, step_index FROM checkpoints WHERE task_id = $1 ORDER BY created_at DESC LIMIT 1;
3
Execute Handler with AI
// Call Gemini for AI tasks const response = await genAI .getGenerativeModel({ model: 'gemini-2.5-flash' }) .generateContent(prompt);
4
Save Checkpoint (Atomic)
BEGIN; UPDATE task_nodes SET state = $1, heartbeat_at = NOW() WHERE id = $2; INSERT INTO checkpoints (task_id, step_index, state) VALUES ($2, $3, $1); COMMIT;
5
Complete Task
UPDATE task_nodes SET status = 'completed', output_payload = $1, completed_at = NOW() WHERE id = $2;
OUTPUT: Worker Result
{ "success": true, "taskId": "uuid", "action": "process", "details": { "output": { ... } } }

Lambda Supervisor Function

Handles API requests via API Gateway. Creates jobs, manages tasks.

INPUT: API Gateway Event
{ "httpMethod": "POST", "path": "/jobs", "headers": { "Authorization": "Bearer x404r_..." }, "body": "{\"name\": \"...\", ...}" }
1
Authenticate Request
SELECT t.id, t.plan FROM api_keys a JOIN tenants t ON a.tenant_id = t.id WHERE a.key_hash = SHA256($1);
2
Check Usage Limits
SELECT COUNT(*) FROM usage_events WHERE tenant_id = $1 AND event_type = 'task_created' AND created_at > date_trunc('month', NOW());
3
Create Job
INSERT INTO jobs (id, tenant_id, name, input_payload, status) VALUES (gen_random_uuid(), $1, $2, $3, 'pending') RETURNING *;
4
Decompose with Gemini AI
// AI decomposes task into subtasks const decomposition = await gemini.generateContent(` Decompose this task into steps: ${taskDescription} Return JSON: { tasks: [...] } `);
5
Create Task Nodes
INSERT INTO task_nodes (job_id, name, task_type, depends_on, status) VALUES ($1, 'parse', 'analyze', '[]', 'pending'), ($1, 'lint', 'validate', '[]', 'pending'), ($1, 'report', 'generate', '["parse","lint"]', 'pending');
OUTPUT: API Response
{ "statusCode": 201, "body": { "jobId": "uuid", "taskCount": 3, "tasks": [ { "id": "...", "name": "parse" }, ... ] } }

🔒 Key SQL Operations

Atomic Task Claiming:
SELECT * FROM task_nodes WHERE status = 'pending' FOR UPDATE SKIP LOCKED LIMIT 1; -- Prevents race conditions -- Multiple workers can call simultaneously -- Each gets a unique task or nothing
Vector Similarity Search:
SELECT context_summary, resolution FROM memory_vectors WHERE tenant_id = $1 ORDER BY embedding <-> $2 LIMIT 5; -- Finds similar past experiences -- Agents learn from history

Crash Recovery — Complete Flow

🔄 Worker A Running
Task: process item 5/10
Heartbeat every 10s
await ctx.checkpoint({ progress: 5, items: [...] });
checkpoint →
💾 CockroachDB
Saved State:
checkpoints: { progress: 5 }
task_nodes.state: { progress: 5 }
heartbeat_at: NOW()
💥 CRASH → Lambda dies
💀 Worker A Dead
Memory = gone
Process = terminated
But state is safe in DB!
60s no heartbeat →
⏰ Reclaim Job
EventBridge triggers reclaim
UPDATE task_nodes SET status = 'pending', worker_id = NULL WHERE heartbeat_at < NOW() - '60s';
claim →
✅ Worker B Claims
Loads checkpoint
ctx.state.progress = 5
Continues from item 5!
let p = ctx.state.progress || 0; // p = 5, not 0! for (i = p; i < 10; i++) {...}
